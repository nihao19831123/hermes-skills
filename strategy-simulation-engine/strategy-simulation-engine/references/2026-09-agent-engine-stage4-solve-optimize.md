# 阶段 4：L3 决策智能（反向求解 solve + 自动寻优 optimize）2026-09-19 实测

适用：仿真引擎已有「正向推演」（参数 → 结果），现在要做**反向**能力：给目标指标值反推参数组合、
在大候选集上自动寻优。这是答辩里最能体现"智能"的一层，也是最容易被"凭什么信你"追问的一层。

---

## 1. 反解必须先做两件事，否则结果不可信

### 1.1 全部候选共用**同一个随机种子**

治具：`seed = derive_seed(基准参数)`，所有 (action, dept, magnitude, years) 组合都用它调 simulate。
若让种子随参数派生（引擎默认行为），变体之间的差异里混进蒙特卡洛噪声，**二分法会收敛到伪解**
（"强度越大指标越高"的单调性被噪声打断）。代价：结果反映的是"同一种子下的确定性比较"，
所以必须把种子写进输出并在报告里给出。

### 1.2 二分前先验证单调性，非单调组合显式标记

端点探测（magnitude=min 与 max 各跑一次）→ 若指标没朝目标方向变化，标记 `monotonicity[].ok=false`
+ 原因文字，**不参与求解**。别沉默跳过（复盘时无法回答"为什么没试这个组合"）。

## 2. 性能坑：`load_world` 每次重解析 2.3MB JSON

实测数据（本项目）：
```python
load_world()                      # 0.050s/次，其中 JSON 解析 0.042s
simulate(runs=4,  density=0.25)   # 0.114s → 其中 ~40% 是 load_world
simulate(runs=8,  density=0.5)    # 0.261s → 其中 ~20% 是 load_world
```
反解全 27 组合要调 simulate 400+ 次 → 122s。修法（两条一起上）：
1. **缓存已解析的 JSON**（模块级 `_HEATMAP_CACHE`），每次调用只重建街道 dict
   （**不要缓存最终 streets 对象**——simulate 会就地改 `s["p0"]/s["pot_pc"]`，缓存会被污染；
   重建 dict 既便宜又安全）；
2. **两阶段求解**：粗筛用低精度档（runs=4/density=0.25）+ 少量二分迭代（4 次，够排序）
   → 取成本最低的 top3 组合 → 只用标准档精算（二分 8 次 + 年限择优）。

结果：122s → **26s**（全科室 27 组合），单科室 14.6s。判据写进自检：全组合反解 < 40s。

## 3. 年限下限：`years=1` 是陷阱

释放曲线在 `years<=1` 时退化为 `L=1.0`（一年满额见效），而成本代理 = 强度 × 年限，
于是**反解永远推荐 1 年**——管理上不成立（战略落地不可能当年满额见效）。
修法：`min_years` 默认 2，并在文档写清理由；保留 `min_years=1` 可复现旧行为。

## 4. 诚实判据三件（专治"一句最优"）

寻优输出必须能回答"为什么第一名胜出"，否则就是"随手拍"。三条自动检测（本项目实测都触发了）：

1. **并列检测**：与前一名收益差异 ≤0.5% → 明说"按收益排名不具区分力"，
   改用「风险更低 / 年限更短 / 空间分布更合意」区分。实测前 2 名差 0.5%（129,755 vs 129,141）。
2. **容量触顶检测**：把可用容量上限算出来对比。本次实测有两类情形，**文案必须分开**：
   - 首选自己触顶 → "总量由容量决定，不由战略参数决定，差异只在空间分布"；
   - 更强的候选触顶（因号源率将达 100% 被风险约束排除）→ "另有 N 个更强方案被排除，
     继续加大强度不再增加总量，须同步扩容"。
   ⚠ 我第一版把两者的条件写成一个 `any("容量上限" in notes)`，导致**首选没触顶却报"首选已触顶"**——
   必须用 `win_capped` 与 `capped` 两个独立布尔。
3. **科室敏感度检测**：某动作下不同目标科室的指标极差 < 1% → 明说"该动作按地理/容量起效，
   科室选择不应作为卖点"。实测医联体各科室极差 **0.00%**（30%/5 年全部触顶 165,468），
   若不检测，寻优会给出"医联体·骨科最优"这种站不住的结论。

## 5. 新增空间指标的口径坑（radius80 / HRI）

- **80% 半径必须由分布重算**，不能沿用老引擎的 `base × (1 − 0.06×…)` 近似缩放——
  两者的**方向都可能相反**：本项目实测专科提升让半径 14.90 → 14.46 km（近端聚焦，收缩），
  医联体 → 24~29 km（向外扩散）。汇报话术要改成「半径变化方向取决于战略的空间分布」，
  否则老叙事"5 年半径扩大"会在现场被自己的数据打脸。
- **HRI 全域口径恒为 1**（分子分母同集合），只有选定区域/区级才有管理含义 →
  作为求解目标时必须强制要求 `streets`/`region`，否则如实拒绝（"全域 HRI 无法作为目标"）。
- 两者都按「出院/人口占比」与 `engine.hri_region` 对齐口径；策略后用 `真实值 + 累计增量` 作为分子。
