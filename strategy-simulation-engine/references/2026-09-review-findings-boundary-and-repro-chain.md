# 独立评审暴露的缺陷类（2026-09，阶段 4–6 交付后）

背景：一次外部对抗性复核（claude code + glm-5.2，只读）在本项目 6 个新模块 + 12 个端点 + 单文件前端 + 两份文档上
报了 15 条（1×P0 / 4×P1 / 7×P2 / 3×P3）。约 3/4 落在**作者自测从未覆盖的路径**：子集口径、类型混淆、未知枚举、以及
"验收表里的 PASS 本身"。以下是按缺陷类提炼的、下次交付前必须自查的清单。

## 1. 子集/选区口径（P0，最致命）

**症状**：带 `streets=[...]` 选区的 run，逐科室人次增量**全部为负**（9/9，合计 −275,913），而同一 run 的总量
`final_add_opd.p50 = +13,756` 为正。**同一份结果里两套数字方向相反** —— 这不是口径能解释的，评委一眼看穿。

**根因（本引擎）**：逐年循环里对选区外个体 `continue`，但**没有把当年的概率写回该个体的行**
（`row_p[i]` 保持 0.0），而基线行 `pself[0][i] = p0 > 0`，于是末端增量 `(0 − p0) × visit_pot` 恒为负。
连带污染帧数据：选区外个体的 `p_self_end = 0`，前端把 `|Δp|` 大的它们判成"被战略触动的焦点个体"。

**修法**：在过滤分支里令概率保持上一年（`row_p[i] = p_prev[i]`，增量自然归零），并让被过滤个体按"战略强度 0"
参与抽样以保留基线选择（而不是被强制编码成"未就诊"）。改引擎公式 → **必须递增 `ALGO_VERSION`**，重建预生成结果集，
复跑差分对拍 + 核心哈希确认**全流域场景（sel=None）零回归**。

**自查方法**：任何带"部分范围/子集"参数的推演，都要断言 `Σ 分项 == 总量` 且**符号一致**。这一条现在应进自检项。

## 2. API 边界校验（P2 级，但其中两条比 500 危险）

引擎公式不许动（零回归纪律），所以校验一律加在 **API 边界**：类型强制 + 范围钳制 + 枚举白名单，非法输入返回 400。

| 输入 | 实际行为 | 应然 |
|---|---|---|
| `years="5"` / `magnitude="0.3"` / `runs="4"` / `density="0.25"` / `…=null` | **TypeError → 500** | 类型强制/400 |
| `kind` 未知或 null | **ValueError → 500**（异常文本外泄） | 白名单 → 400 |
| `target=0` | **ZeroDivisionError** | 400 |
| `max_years=0` | **KeyError: 'value'** | clamp 到 ≥1 或 400 |
| `depts="心内科"`（字符串） | 被当字符序列 → 科室"心"，**静默给出方案** | 400 |
| `actions=["bogus"]` | **静默返回 bogus·心内科 方案**，无校验 | 白名单 → 400 |
| `streets=["假街道"]` | 引擎 `raise SystemExit` → 500 | ValueError → 400 |
| `magnitude=5.0`（500%） | 正常出结果，无上限 | clamp [0,1] 或 400 |

**判定优先级**：**"不报错但给无意义结果"比 500 危险**（答辩现场手改 JSON/第三方调用时无人察觉）。凡枚举/列表类参数，
先校验再进引擎。已正确处理的可以照抄：`years=0/-3` → clamp 到 1 年 ✓｜`hri_region` 不给区域 → **诚实拒绝** ✓｜
越界 `agent_id` → 400 ✓｜不存在的 `run_id` → 404 ✓。

## 3. 复现链锚定（P1，最容易被评委现场打脸）

`data_version` 由业务库的 **size + mtime** 派生 → 派生种子 → 全部数字。因此**任何对业务库的写入**（`promote`、
旧端点被点一下、评委试用）都会改种子，让文档里的数字**当场对不上**。本项目实测：文档记 `+220.8% / ρ0.916`，
换 data_version 后复算 `+225.1% / ρ0.941`；而**未受影响的回测数字逐位一致**（MAPE 50.13% / 4.42%）。

**纪律**：① 文档里的每个数字锚定 **结果库 run id + data_version + 种子**（"以 run #N 为准"）；② 验收文档加粗声明
"任何写业务库的操作都会使文档数字失配"；③ 演示前**不要**点会写库的旧端点（含"点一下试试"）。

## 4. 冻结基线的正确写法（否则复核者必报误报）

基线文件必须记成：`hash + 本次排除的字段清单 + seed + data_version`。
本项目基线只存了 hash，于是复核者拿"已新增两列概率的 trace"去比旧 hash → 报"哈希不可复现"（误报）；
按"**剔除新增附加列 + 归一化 mtime 派生字段**"复算即精确匹配。作者侧的对拍脚本要把"排除清单"写成常量并打印出来。

## 5. 验收文档纪律（P1）

- **附录编号必须与正文一一映射**：本项目正文 §七 用 6.1–6.12，附录又从头编了 6.1–6.17 → 两套编号撞号，
  按附录编号查不到正文条款，证据链断。附录一律用 `6A.1…` / 加映射表。
- **未达标项必须显式写 FAIL + 整改口径**：`grep 未达标|FAIL` 在验收文档里 0 命中 = 验收诚信问题（比性能不达标更伤）。
  正确写法：`首屏 | FAIL（实测 2.5s，判据 ≤2s）| 整改：默认改演示档 0.52s 可达标`。
- 像素计数/截图类"证据"必须配**可重跑的脚本**（点阵计数可直接由帧数据的长度断言，不需要肉眼看图）。

## 6. 前端"零计算"红线的兜底陷阱（P1）

"前端不做任何效用/概率计算"是红线，**任何 fallback 插值都算违反**——即使 live 路径永不触发（本项目：帧数据带
逐年概率时走后端值，缺失时前端做线性插值兜底）。缺数据的正确行为是**不渲染该口径（置灰/沿用上一帧）**，
不是浏览器里补算。自查：`grep` 前端里所有对概率/效用/期望值做算术的表达式，逐个判定来源。

## 7. promote 映射到既有结构的三个坑（P2）

1. **字段层级**：`radius80/hri` 在 `interval`（即 `metrics`）里，从记录顶层读会得到空 → 报表出现 "— km"。
2. **键名必须与引擎同名字段逐字核对**：`opd_last` vs 引擎实际的 `opd_last_year`，写错一个键 → 该字段**恒为 0**
   且不报错（逐年住院增量被系统性低估）。
3. **既有无守卫的老页面会被空值打穿**：老前端渲染 `y.radius80 + 'km'` → 显示 "nullkm"。映射产出可空字段时，
   **必须同时给老页面的渲染处补空值守卫**（`x == null ? '—' : …`），否则只在报告生成器里加守卫是不够的。
