## 1. 原型数据从项目真实文件抽取（只读，不改项目）
来源 `backend/heatmap_data.json`（2.3 MB，**只用 Python json.load，不要用 Read 整读**）：

| 需要的 | 取自 |
|---|---|
| 街道名/区/质心 | `street_geo.features[].properties.{name,district}` + `coords[街道]{lng,lat}` |
| 街道边界轮廓 | `street_geo.features[].geometry.coordinates[0]`，降采样到 ≤28 点（每 k 个取一个）|
| 街道人口/门诊/出院 | `population["2025"]` / `opd["2025"]` / `discharge["2025"]` |
| 街道科室结构 | `departments[街道]{科室:数}` —— **现有数据只有 9 类科室**（含"其他"），不是 106 科室 |
| 竞争医院 | `hospitals[]`，取 `grade ∈ {三甲,三乙,三级}` 且**排除本院**（名称含"第三人民"）→ 实测 22 家 |
| 三医坐标 | 与 `engine.py` 保持一致：`(120.3884087, 36.1795722)` |

距离口径**必须照抄 engine.py**，否则同一街道在引擎与原型上距离不一致：
`dlat=(lat-lat2)*111.0; dlng=(lng-lng2)*89.6; d=sqrt(dlat²+dlng²)`。
HRI 复用引擎口径（出院份额 ÷ 人口份额），归一到 [0,1] 当"忠诚度"。

## 2. 数据锚定基线：别手拍效用系数（领域专家一眼看出荒谬）
用户是三甲/三乙一线管理人员，**"30 km 外的街道怎么会有 24% 选你们"这种数字会立刻被否**。
做法：每个街道的基线"选择我院概率" `p0` 由**真实数据分位**映射，而不是靠调系数：

```
raw = 街道门诊 / 街道人口            # 空间真实结构
pct = 该街道在 134 街道中的分位(0..1)
p0  = clamp(0.05 + 0.58 * pct**1.5, 0.05, 0.63)   # 实测：min .050 / 中位 .257 / max .630
```
近端（李沧 <3 km）p0≈0.60–0.63，远郊（大村镇 233 km）p0≈0.05 —— 与常识一致，专家不会挑刺。
竞争基线 `q0 = clamp(0.14+0.45*(1-min(1,dc/15))*tier, 0.05, 0.62)`（tier：三甲 1.0/三乙 0.6/三级 0.4）。

**抽样规模**：`N_s = clamp(round(pop/4000), 8, 40)`；密度档 ×0.55/×1.0/×1.6 →
实测 **1,472 / 2,635 / 4,219** 个智能体（原设计写"pop/20000、10–40"只有 ~1,340，属算错，已回写修正）。

## 3. 三种动作必须作用在不同距离带（否则图上没差别）
```
sens   = 0.45 + 1.0*distSens_i            # 个体距离敏感度（异质性来源；distSens∈[0.55,1.5]）
wNear  = exp(-ds/15) * sens               # 专科提升：近端先亮
wFar   = (1-exp(-ds/20)) * (0.6+0.7*sens)# 医联体：远郊被激活
L      = 1/(1+exp(-1.7*(t-(years-1)/2)))  # logistic 采纳曲线：效果不是第一年到位
match  = (该智能体偏好科室 == 目标专科) ? 1 : 0.12
m = 1 + L*(1.0*spec*wNear + 0.95*al*max(wFar,0.15) + 0.85*cap*0.85*sens + 0.14*loyalty)
p = clamp(p0*m, 0, 0.95)
if action=='alliance': p = clamp(p + L*al*max(wFar,0.15)*0.85*(1-p), 0, 0.95)  # 激活"原本不来"的人
q = clamp(q0*(1+0.18*L*cap), 0, 0.9)
choice = r<p ? 我院 : (r<p+q*(1-p) ? 竞争 : 未就诊)     # r 取自固定种子 PRNG
```
实测末期对比（强度 25%、5 年、心内科）：**专科提升 近端 72%／远郊 16%；医联体 近端 70%／远郊 41%；扩容 近端 79%／远郊 18%**。
"换动作再看一遍"是答辩最有记忆点的一帧（已写进详细设计 §7.6 脚本第 4 帧）。

### 8.2 动画循环（"活着"的来源）
- 单一 `requestAnimationFrame` 循环：每个个体有 `tx,ty`（目标格位）与 `x,y`（当前），每帧按 `d>0.35` 做插值并记录拖尾；`glow` 每帧衰减 `dt/900`。
- **静息降帧**：>9k 点且无移动且未播放时，每 3 帧才重绘一次（省电、避免风扇狂转）。
- 年份推进 = 重算 `tx,ty`（`reTarget(false)` 动画式；初始化/缩放用 `reTarget(true)` 瞬移）。
- 播放节奏 1.7 s/年，避免帧太快看不清"谁变了"。

### 8.4 验收钩子升级（比 pixelStats 更硬的证据）
- 在 `dot()` 里累加 `window.__dots` / `window.__dotsBy[state]` → **断言"每个视图到底画了多少个点、各状态各多少"**。
  实测：人群迁徙 11,884 ｜ 地图波前 11,884 ｜ 双蜂群对比 23,768（两屏）｜ 街道阵列 1,707（前 30 街道）。
  （注意：分带/迁移流是内联 `ctx.arc` / 画柱子，不走 `dot()`，计数器为 0 属正常——**别把计数器的盲区当成"没画"**，要用 `pixelStats()` 交叉验证。）
- 单帧耗时基准：1.2 万点 2.8 ms ／ 2.5 万点 5.1 ms（地图）/ 5.3（波前）/ 7.0（分带）→ 60 fps 预算 16.7 ms，余量充足。
- **动画要用两步法测**：`setYear()` 后立即返回"待移动点数/平均剩余距离"（实测 11,884 个 / 225 px），**下一次调用再测同一指标**（实测归零 + `animating=false`）＝ 证明真的动过。一次调用里测必定是 0，会误判成动画没生效。
- 缩放验证：取两个固定个体的屏幕间距，1× → 3× 应为 20px → 59px（`d3 > 2.5*d1`）。
- 页面内自检还要报"区格间距 vs 点直径"，让用户自己看到可读性数字。
