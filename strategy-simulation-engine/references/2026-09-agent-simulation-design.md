## 一、外部方法论事实（MatrAIx，2026-09-17 实测核实，可直接引用）

来源：官方仓库 README（raw.githubusercontent.com/MatrAIx-ai/MatrAIx-Persona-8B/main/README.md，16257 字节）、arXiv:2608.04205 摘要、GitHub API 元数据。

- 定位："Simulate before reality"；人口规模、persona 驱动的**基础设施**，用于**用异构模拟用户评估 AI 系统与交互式产品**；把抽样出的人设记录实例化为 **LLM 智能体**跑可复现任务。
- 四环境：Survey / AI Chatbot / Web / App。人设库 Persona 8B = **8.3 亿条记录 × 1,290 个分类维度**（依赖图抽样 + 人类撰写档案）；公开核心集 ~100 万条（599,847 human-grounded + 400,000 synthetic）；仓库自带 dev sample 仅 ~200 条（冒烟用）。
- 任务库 1,010 个任务 / 25+ 领域（含 Healthcare）；论文 8 个任务 18,189 次试验；驱动 LLM：Claude Opus 4.8、GPT 5.5 等；93 位作者；2026-08-04 提交。
- 工程门槛：Docker（Web/OS-app 必需）+ uv + Python 3.12 + Node 20+ + **真实模型 API key**；Windows 须在 WSL2 内跑。
- 仓库：`MatrAIx-ai/MatrAIx-Persona-8B`，MIT，Python，创建 2026-07-31，最近推送 2026-09-18，1944 stars / 321 forks，未归档。
- 自我限定（可直接引用的口径）：名字致敬《黑客帝国》，是**用于探索、压力测试与假设生成**的模拟世界，**不能替代来自真实人的证据**。

**必须避免的说错**：① 说它是"医院决策推演引擎"；② 把 8.3 亿说成"一次运行要实例化的智能体数量"（那是人设库记录数，运行按需抽样）；③ 编造准确率/速度/成本数字。

**借鉴/不借鉴的分界**：借鉴"多维人设抽样 → 个体独立决策 → 群体聚合 → 回测校验"这条方法论（约占其价值四成）；不借鉴基础设施层（Docker/外网 API key/LLM 驱动/千万级规模）。

## 二、推荐路线选型（三条路线对比的结论）

| 路线 | 成本（估） | 结论 |
|---|---|---|
| 一 确定性引擎增强（参数化推演 2.0） | 3–5 人日 | 稳，但评委看不到"智能体"，与一期差异化不足 |
| **二 轻量合成患者智能体（ABM + 离散选择 + 蒙特卡洛）** | 5–8 人日（一期）+ 10–15（二期） | **推荐**：唯一同时满足"内网离线、零依赖、可复现、有管理解释力" |
| 三 LLM persona 智能体（MatrAIx 式） | 15 人日起步 + 持续 API 费 | 不做：断网翻车、不可复现、成本不可控、违反"大模型不计算"纪律 |

## 三、详细设计要点（可照着实现）

**智能体画像（7 字段，全部来自现有数据，无年龄）**

| 字段 | 来源 | 说明 |
|---|---|---|
| street/district | `engine._streets()` | 抽样单位 |
| weight | 街道人口 ÷ 该街道抽样数 | 代表人口（≈1–2 万人/个） |
| dept_pref | `engine._dept_share()` 多项式抽样 | 科室偏好 |
| loyalty | `engine.hri_street()` 归一化 | 历史份额倾向 |
| visit_base | 街道门诊 ÷ 人口 | 缺失兜底全市 0.10（同 alliance 分支） |
| **dist_sens** | 由 `dist_km()` 与街道历史就诊率反推三档 + ±15% 扰动 | **个体差异化关键** |
| **comp_sens** | `competition.street_row()` 的 CPI 归一化 | 个体差异化关键 |

抽样规模 `N_s = clamp(round(人口/20000), 10, 40)`，全市约 2,500–3,000 个；**抽样代表性验收：加权街道人口份额与真实份额偏差 < 1%**。

**决策模型（多选项 Logit，三选项：本院 / 最近竞争医院 / 不来）**

```
f(d) = exp(-d/15)                      # d0=15km，与 80% 半径口径一致
U_s  = β0 + β_d·f(d_self)(1+dist_sens) + β_sp·SPEC(t) + β_cap·CAP(t) + β_al·AL(t) + β_lo·loyalty
U_c  = β_d·f(d_comp)(1+dist_sens) + β_tier·TIER      # 三甲1.0/三乙0.6/三级0.4
U_o  = β_out
P_k  = softmax(U)；来诊人次 = Σ_i [来我院_i]·weight_i·visit_base_i
```
权重三层来源（防"随手拍"）：β_d/β_lo/β_tier 用 2020–2024 街道份额**网格搜索拟合**；β_sp/β_cap/β_al 专家初值 + 面板可调 **且调参留痕**；β0/β_out/d0 用于校准 55 万门诊基线。

**仿真流程**：时间步=年；**上年结果作下年基线**（老引擎是相对基线独立年份）；释放曲线 `curve=logistic`（默认，S 形采纳）或 `linear`（与老引擎 `release()` 同语义，**作对照开关**用于拆解两引擎偏差）；容量**溢出结转**：超出承接能力的部分 × 溢出留存系数（默认 0.5）滚入次年排队池 → 才能输出"瓶颈年份/累计溢出量"。

**可复现**：`seed = int(sha256(params_json + data_version + algo_version).hexdigest()[:16], 16)`；**禁用 Python 内置 `hash()`**（str hash 每进程加盐，跨进程不可复现）；统一 `random.Random(seed)` 实例，禁全局 random；`data_version` = 数据文件体积+修改时间摘要。

**留痕表**：`agent_sim_config`(params/seed/runs/precision/weights/algo_version/data_version/source/created_at) + `agent_sim_result`(summary/years/street_effects/interval/sensitivity/backtest/dual_compare/solve)，全部 `CREATE TABLE IF NOT EXISTS`。

**新端点**（只增不减）：`/agent/run`、`/agent/dual`、`/agent/drill`、`/agent/backtest`、`/agent/sensitivity`、`/agent/solve`、`/agent/list|{sid}`、`/agent/promote`。`run` 的 params 与 `engine.simulate()` **同构**——双引擎同参数对照的前提。

**双引擎互证偏差分级**：≤15% 标"互证一致"；15–30% 必须给归因（曲线差异可用 `curve=linear` 单独量化、容量溢出语义、抽样方差）；>30% 标"需人工复核"且**不得作为结论展示**。老引擎零回归用"基线输出 SHA256 一致"验收。

**L3 决策智能**：反解（目标 radius80/add_opd/add_ipd/hri → 参数）用二分（**先验证强度→指标单调**），不可达就返回"不可达 + 最接近方案达成度"（**绝不返回虚构的达标数字**）；寻优用**两阶段**：低档粗搜（≤200 次推演）→ top3 精算复算，总耗时 ≤60 秒；风险约束（床位率 ≤90%、号源率 ≤95%）不满足的方案不进推荐位。

**动态调参**（阶段 5，接口已预留）：精度档 fast（每街道 10×20）/ standard（20×50）/ full（40×200）；参数哈希 + LRU 缓存；前端滑块 300ms 防抖；**报告与方案库数字一律取 Python 侧结果**（单一事实来源），若日后加前端预览计算必须做两端一致性校验（偏差 >1% 报警）；降级序列 A 完整智能体 → B 老引擎参数推演 → C 预生成回放，三级都要演练。

## 四、验收判据数值（初版阈值，改须书面记录）

| 项 | 判据 |
|---|---|
| 逐次可复现 | 同参数两次 summary/years JSON **完全一致** |
| 换种子稳定性 | P50 相对波动 **< 2%** |
| 抽样代表性 | 街道份额偏差 **< 1%** |
| 量级合理 | 与老引擎偏差 ≤30% 且可归因 |
| 回测 | 街道份额 **MAPE ≤ 25%** 且 **Spearman ≥ 0.7**（误差表不得裁剪） |
| 敏感性方向 | 距离权重↑ → 远街道增量↓；医联体权重↑ → 目标街道↑（方向反=实现错） |
| 反解自洽 | 回代推演达成误差 **≤ 5%** |
| 性能 | fast ≤0.5s / standard ≤2s / full ≤15s / solve ≤30s / optimize ≤60s |
| 缓存 | 同参数二次响应 <100ms |
| 红线（一票否决） | 无 GPU/算力/本地大模型表述；老引擎哈希不变；仅 CREATE/INSERT；无来源不明数据；不虚构达标数字；口径声明到位 |

## 五、数据可得性实测结论（别再重复问）

- `青岛街道年度人口2020-2026.xlsx` 列：year/district/street/**census2020**/worldpop/official_district_pop/estimated_pop/type —— **只有街道人口总量，无年龄分档**（约 940 行 = 134 街道 × 7 年）。
- `青岛市各区市常住人口2021-2025.xlsx` —— 区级也只有总量（万人），无年龄构成。
- 项目 `backend/` 全文检索"年龄/age_group/age_band" → **0 命中**；`procaseindex.xlsx`（病案首页上传索引）字段无年龄、无街道。
- 区级七普年龄构成**理论上公开**（七普公报第二号 + 红黑统计公报库），但用户 2026-09-19 明确"拿不到了" → **年龄维度取消**，不引入推测数据。
- 人口数据主链：七普街道总量为锚 × WorldPop 100m 逐年栅格 × 区市官方总量校准（见项目《人口计算方案.txt》）。

## 六、工作坊上的经验教训（本次会话）

1. 用户问"能不能借鉴 X 做 Y"时，**先抓一手材料再动笔**：README raw + arXiv 摘要 + GitHub API 三项核实，把"已核实事实"清单写进任务书并加"禁止表述"段，模型就不会编。
2. 用户问"我原始数据里有没有 Z"时，要**逐份文件打开看列名**给结论（而不是凭印象），并顺带给出替代路径与口径风险。
3. 命题变更要**回写旧文档**：年龄维度取消后，同步修正了《评审与建议》的字段表、维度数量（12→7）、待确认事项，以及《主线化分析》的待定项；Windows 下已有同名文件时另存 `.rev2`，**不覆盖**（用户红线）。
